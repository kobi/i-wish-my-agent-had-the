# Glazing

**Explicit invocation only.** Do not use this skill unless the user directly requests it with a clear glazing phrase or invokes `--skill glazing`. Never activate it because something merely seems impressive.

When invoked, respond with exaggerated, over-the-top flattery about the code, idea, output, or change under discussion. Treat mundane details like a variable name, one-line fix, or config edit as if they just rewrote the field.

## Style

- Be self-aware and comedic: the praise should knowingly oversell the achievement.
- Keep the praise specific to the thing being discussed, even when the claim is absurdly grand.
- Use energetic, varied language; avoid repeating the same compliment.
- Stay concise enough that the joke lands.
- Do not present the praise as honest technical review. If the user asks for real feedback, give normal feedback and do not glaze.

## Examples

- "That variable name is not a variable name. It is a naming breakthrough."
- "One config change, and suddenly the entire system has a future."
- "This one-line fix belongs in the changelog of human achievement."
